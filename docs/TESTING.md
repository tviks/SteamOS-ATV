# Проверки комплекта

## Выполнено 27.09.2026

Windows, Python 3.14: `python -m unittest discover -s tests -v`. Проверены состав runtime, LF без BOM, фиксированный релиз/контрольные суммы, наличие исправлений пульта, отсутствие адреса конкретного Deck и переменной SSH-пароля в переносимых скриптах. Проверен состав готового ZIP: нет `local`, `archive`, known_hosts, Android-образов и `.pyc`.

Чистые функции mDNS проверяются без открытия сетевого сокета: формат четырёх DNS-записей, A-запись, длина TXT, TTL, кодирование и чтение DNS-имён.

На уже настроенном Steam Deck архив распакован во временный каталог `/tmp`. Выполнены те же тесты с доступным Linux Bash: `bash -n` для всех исполняемых shell payload и установочных скриптов. Проверен вывод `install.sh --help` и выполнен read-only `doctor.sh`: точное соответствие host bundle SteamOS 3.8.28, наличие образов, helper, udev-правила и доступ к ограниченной команде sudo. Контейнер и установленная интеграция этими проверками не изменялись.

Дополнительно проверены синтаксис sudoers через `visudo -cf` и правило udev через `udevadm verify` на Deck.

## Исправление журнала запуска

Дополнительно проверены Linux-тесты logging helper: два последовательных открытия журнала, stdout launcher как pipe (не regular file), автоматическая замена старого недоступного журнала с сохранением предыдущего. На Deck исправленный ярлык запущен из Steam после загрузки системы с отсутствующими Binder-узлами. Затем TV остановлен и повторно запущен через Steam. В обоих случаях Android загрузился (`sys.boot_completed=1`), а `steam-launch.log` остался `deck:deck 0644`, включая промежуточную остановку контейнера. Новая отдельная перезагрузка Deck после исправления не выполнялась.

## Что не подтверждено

Полный проход `install.sh --bootstrap` на очищенной SteamOS пока не выполнен. Подтверждена работа исходной конфигурации, на которой основан комплект; это не эквивалент полного теста нового автоматизированного установщика. В частности, скачивание и развёртывание с нуля в ходе проверки комплекта не повторялись.

Не проверены другие версии SteamOS/ядра, другие пользователи, Ethernet, несколько одинаковых Deck в одной сети и альтернативные образы Android. Установка зависит от доступности совместимого стороннего bundle и закреплённых образов автора.

## Как повторить проверки

На Windows:

```powershell
python -m unittest discover -s tests -v
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-release.ps1
python -m unittest discover -s tests -v
```

Сборка использует встроенный `tar.exe` Windows (bsdtar) для ZIP с переносимыми именами. Архив содержит только белый список файлов и каталогов. Временный staging удаляется после проверки абсолютного пути; исходные файлы не удаляются.

На Deck, из каталога распакованного комплекта:

```bash
bash scripts/verify-on-deck.sh
visudo -cf runtime/waydroid-atv16-sudoers
udevadm verify runtime/72-waydroid-atv16-remote.rules
```

Проверка самого ZIP пропускается внутри распакованного комплекта, если рядом нет `dist/android-tv16-steamdeck.zip`; она выполняется в Windows-проекте после сборки.

## Приёмка новой установки

1. На чистой SteamOS локально из Desktop Mode выполнить `bash install.sh --bootstrap` и затем один раз `bash add-to-steam.sh`.
2. Из Gaming Mode запустить Android TV 16 и завершить первичную настройку.
3. Проверить крестовину/левый стик, A и B.
4. Сопрячь Google TV, проверить вправо/ОК/назад: ровно один шаг, без разрыва соединения.
5. Закрыть TV через Steam, повторно запустить и проверить сохранение приложений/сопряжения.
6. Перезагрузить Deck и повторить проверки обоих способов управления.
7. При закрытом TV выполнить `bash install.sh --repair`, убедиться, что данные сохранились.
