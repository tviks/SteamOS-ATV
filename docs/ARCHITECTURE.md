# Как устроен запуск

Журнал launcher открывает отдельный пользовательский `tee`-процесс. Привилегированные процессы и контейнер получают stdout/stderr как pipe, не как дескриптор `steam-launch.log`: смена владельца унаследованного дескриптора больше не делает файл недоступным `deck`. Недоступный старый журнал переносится в один `steam-launch.previous.log`, после чего создаётся новый пользовательский журнал. Восстановление не требует root-команды, способной менять права произвольного пути.

```text
Steam → Android-TV-16-Steam.sh → Cage (X11, 1280×720) → Waydroid UI
                          ↓ sudo: только check/start/stop/input
                /etc/waydroid-atv16/control
                          ↓
             bind mount TV state → /var/lib/waydroid
                          ↓
             Waydroid container + controller hotplug

Телефон → Wi-Fi Deck:6466/6467 → socat → Android:6466/6467
              ↑ mDNS                ↓
                              virtual-remote → Android input
                              (Steam/gamescope исключены)
```

Конфигурация поддерживает стандартный Deck: пользователь `deck`, UID 1000, `wlan0`, сеть Waydroid `192.168.240.0/24`. LAN-адрес определяется динамически; адрес конкретного устройства пользователя не зашит в переносимый комплект.

Root helper установлен root:root и принимает только четыре фиксированные команды. Sudoers не разрешает произвольный shell или выполнение пользовательского скрипта без пароля. Установщик использует обычный запрос sudo и не сохраняет пароль. Перенос всех конфигураций на произвольного Linux-пользователя не поддерживается.

На время запуска ограничивается глобальный `kernel.pid_max` до 65535: Android 16 на этой конфигурации плохо переносил более высокие PID. При нормальном выходе прежнее значение восстанавливается. Это влияет на весь хост, не только контейнер.

Все три Binder-устройства берутся из одного набора `anbox-*`; смешивание обычного Binder и binderfs вызывало сбой. Их создание делегируется root-owned функции `validate_binder` установленной основы.

Оригинальные образы не редактируются. Wrapper bpfloader расположен в overlay; оригинальный бинарник копируется из закреплённого system.img рядом. Wrapper передаёт `ANDROID_FILE__dev_kmsg=3` с открытым файловым дескриптором, пишет диагностический вывод в `/data/bpfloader-debug.log` и сохраняет код выхода оригинала.

Android 16 в этом контейнере не создавал нужные event nodes. Hotplug helper слушает udev и передаёт только виртуальный Steam Input `28de:11ff` и Google `18d1:0100` с именем `virtual-remote`. Узел uinput в Android имеет system:system и 0660; host event node Google-пульта имеет root:root и 0600. Контроллер Deck этим udev-правилом не затрагивается.

Публикация Google TV использует stdlib Python, а не изменение глобальных параметров Avahi. Имя `Steam Deck Android TV` и host `steamdeck-androidtv.local` фиксированы: комплект рассчитан на один такой Deck в сети. Для нескольких Deck нужны уникальные DNS-имена; это не автоматизировано.

При жёстком завершении/сбое Steam EXIT trap может не выполниться. Перезагрузка является безопасным способом очистить runtime mounts/services/firewall rules. Не запускайте другой профиль поверх зависшего TV.
